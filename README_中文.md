# GitHub 发布包使用说明

本目录是准备上传 GitHub 的独立软件与数据版本，原交付目录未覆盖。包括106份补充数据、M1/M2重建程序、M3/M3B完整科学程序及保存轨迹、系数证据和核验文件。两份作者Word初稿与审稿回信保留在本地，不放入这个公开仓库。

## 先运行什么

1. 只检查文件有没有缺失或变化：在本目录运行 `python verify_release.py`，不需要安装科研依赖。
2. 要运行科研程序：使用 Python 3.11，按照英文 `README.md` 的 Quick start 安装锁定依赖。
3. 先运行 M1/M2 的 `verify` 和 `reproduce`，再运行只读 M3/M3B 检查。新结果放在 `runs/`。
4. 想看每个程序能做什么、哪些不能重新运行：打开 `RUN_STATUS.md`。

M1/M2是新重建的可执行核心，不是找回原先删除的完整发布包。核心预测、表格复算、Gate、拟合和单例BSM1参考可以执行；原动态guard和系数敏感性执行器仍缺失。M3/M3B保留完整研究程序和原始保存轨迹；本发布入口先检查保存结果，不代表重跑了全部长时积分。

本次另加了 `runtime_guard_reconstructed_20261104`：这是新的22列输入检查和路由程序。它会提示“输入无效，请停止”“可以进入冻结模型核验”“必须先调用BSM1”。低温/动态的自动BSM1执行器仍需另行集成；本接口不会把路由成功写成最终达标。

完成环境安装后，统一检查命令为 `python -B run_checks.py --output runs/check_01`；加入 `--extended` 还会运行M1/M2预测、Gate重放和一个新的恒定工况BSM1示例。输出目录必须是新目录。实际发布验证范围见 `release_validation.json`。

## 公开前还需要填什么

- GitHub仓库必须真正创建并上传后，才能在论文和回信中填写真实链接。
- 作者代码采用哪种许可证由作者决定；目前没有擅自添加MIT等授权，见 `LICENSE_STATUS.md`。
- `CITATION.cff`的标题和作者取自当前正文；有正式发表信息后再补DOI。
- 最终论文定稿后，需要核对其附件名称与仓库版本一致。原交付目录的摘要和引言保持中文，没有在本轮翻译。

历史JSON、CSV和日志内的一些旧电脑路径是原始出处记录。为保证源文件哈希可核对，未批量改动这些科学证据。当前运行入口使用相对路径，不要求读者建立原来的磁盘目录。

上传后不要让Git自动更改换行符；请保留 `.gitattributes`。本包的科学代码、数据、第三方许可证和失败记录均按原身份保留。`RELEASE_MANIFEST.json`是本次发布文件清单，不替代各科学包内部的冻结清单。
